# Data model

PostgreSQL, UUID primary keys, timezone-aware timestamps. Definitions live in
`backend/app/db/models.py`; the schema is created solely by Alembic migrations,
and CI fails if the two drift.

## Tables

### `users`
Email (unique, indexed), Argon2id `password_hash`, `role`, `status`
(`pending` → `active` → `suspended`), verification and login timestamps,
suspension reason. Deleting a user cascades to every dependent row.

### `sessions`
`token_hash` (unique) — the **digest** of the opaque session token; the
plaintext exists only in the client's cookie. Also `csrf_token_hash`,
`expires_at` (absolute), `last_seen_at` (drives the idle timeout), `revoked_at`,
and a coarse `user_agent_family` for the user's own session list. **Never an IP
address.**

### `email_tokens`
Single-use verification and password-reset tokens, stored as digests with a
purpose, an expiry, and a `consumed_at` marker. Issuing a new token of a purpose
consumes any outstanding one.

### `analyses`
The central record.

* Ownership: exactly one of `user_id` or `guest_token_hash` is set, enforced by
  a check constraint. `guest_expires_at` bounds anonymous access.
* State: `queued` → `running` → `completed` | `failed`, with `started_at` and
  `completed_at`. Transitions are validated in code; terminal states are final.
* Counts: words, characters, paragraphs — safe metadata, not content.
* Results: `raw_model_score` (the model's own output) is stored **separately**
  from `public_score` (0–100, range-checked), alongside `label`, `reliability`,
  `reliability_reasons`, `window_stability`, `diagnostics`, and
  `integrity_warnings`.
* Provenance: `model_metadata`, `calibration_version`, `detector_version`, so a
  stored result stays interpretable after the model or calibration changes.
* Failure: a short `failure_code` only — never exception text.
* Content: `encrypted_text` holds an AES-256-GCM envelope, and only when
  `store_original_text` is true. Guests can never set it.

### `analysis_segments`
One row per paragraph, unique on `(analysis_id, index)` so ordering is stable
and a retry cannot duplicate them. Carries its own scores plus `too_short` and
`grouped_with_context`, which are why the UI can say "not scored" honestly.
Paragraph text is encrypted, and present only when the parent analysis retains
text.

### `feedback`
A verdict (`agree` / `disagree` / `unsure`) and an optional comment about the
*result*. `user_id` is `SET NULL` on user deletion so aggregate feedback
survives an account deletion without identifying anyone.

### `audit_logs`
Administrative and security events: actor, action, target, and structured
context. `actor_identifier_hash` is a keyed digest — **never a plaintext IP**.
Sensitive keys are stripped from `context` before insertion.

### `system_settings`
Typed, admin-editable runtime settings. `value_type` is enforced on update, and
`bool` is rejected for numeric settings because `bool` subclasses `int`.

## What is deliberately absent

There is no column anywhere for a plaintext session token, a plaintext
verification or guest token, a password, or an IP address. Submitted text exists
in exactly one place — `analyses.encrypted_text` and
`analysis_segments.encrypted_text` — always encrypted, and only when the owner
asked for it.

## Enumerations

PostgreSQL `ENUM` types store the lowercase **member values** (`user`, `active`,
`queued`) rather than the Python member names, so the database is readable
without knowing the source.

The autogenerated `downgrade()` dropped tables but left these types behind,
which made a downgrade/upgrade round trip fail with `DuplicateObject`. The
initial migration adds explicit `DROP TYPE` statements, and CI exercises the
round trip.

## Retention

| Data | Removed |
| --- | --- |
| Guest analyses | After `ORIGINLENS_GUEST_RETENTION_HOURS` (default 24) |
| Any analysis | After `ORIGINLENS_ANALYSIS_RETENTION_DAYS` (default 365) |
| Expired sessions | On the retention sweep |
| Everything owned by a user | Immediately on account deletion |

The sweep is a Celery task and can also be run synchronously with
`python -m app.cli retention-sweep`. Retention is enforced by deletion, not by
policy alone.
