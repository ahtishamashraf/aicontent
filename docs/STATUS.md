### Real model inference

Downloading a published checkpoint is blocked here (see below), so the provider
was exercised against a **locally-constructed** safetensors checkpoint with real
PyTorch and Transformers. That is not a substitute for evaluating a published
detector, but it does verify the provider's code paths: loading, label
resolution, tokenizer windowing, inference, finiteness, CUDA refusal, and
rejection of generic `LABEL_0`/`LABEL_1` checkpoints.

`scripts/model_smoke.py` was run against that checkpoint and passed, printing
the observed score without asserting it.

This found two real bugs that no unit test could have:

1. `prepare_for_model` returned 1-D tensors, so the model unpacked the shape as
   `(batch, seq)` and **every real inference raised `ValueError`**.
2. Transformers 5 removed both `prepare_for_model` and
   `build_inputs_with_special_tokens`. The provider now derives the
   special-token wrapper by encoding a probe token with and without special
   tokens and diffing them, which works across both major versions.

### Security posture

Verified by test:

* Production settings refuse the fake detector, debug mode, insecure cookies,
  placeholder or short secrets, `localhost` hosts, metrics without a token, and
  a loosened rate-limit multiplier.
* The provider registry independently refuses to build a fake provider in
  production.
* Argon2id hashing; only digests stored for session, CSRF, guest, verification,
  and reset tokens.
* AES-256-GCM round trip, with tampering rejected.
* CSRF rejects missing and forged tokens; safe methods are exempt.
* Sessions: rotation on login, revocation on logout and suspension, absolute
  expiry, idle timeout.
* IDOR: one user cannot read or delete another's analysis; a guest result is
  unreachable without its token, including after expiry.
* Admin routes refuse anonymous and ordinary users at both UI and API layers;
  a suspended administrator loses access immediately.
* SQL injection payload in the admin search is treated as a literal.
* Rate limiting enforces its limit and writes no plaintext identifier to Redis.
* A sentinel string submitted for analysis appears in neither captured logs nor
  audit records.
* Malicious documents refused: path traversal, absolute paths, symlink members,
  decompression bomb, excessive member count, encrypted PDF, malformed PDF,
  image-only PDF, binary `.txt`, signature/extension mismatch, oversized upload.
* `pip-audit` on `requirements.lock` and `npm audit`: **no known
  vulnerabilities**.

## Not verified, and why

### Real-model evaluation against a published detector
`huggingface.co` is blocked by this environment's egress policy (HTTP 403 on
`CONNECT`; the proxy documents that policy denials must not be retried). No
published checkpoint could be downloaded, so:

* `make model-smoke` against a **production** model is **unverified here**. It
  is implemented, and was verified against a locally-built checkpoint.
* `make evaluate` was run against the checked-in fixture set with a real model
  loaded, and correctly withheld every metric the ten-sample size cannot
  support. It has **not** been run against a real labelled corpus.
* **No accuracy figure exists for this system, and none is claimed.**

Operator action: run `make model-download && make model-smoke && make evaluate
--dataset <your corpus>` in an environment with model access before relying on
any result.

### Running containers
The Docker **CLI and Compose are present but no daemon is available**, so:

* Both Compose files were validated with `docker compose config` (passing), and
  the resolved output was asserted to show migrations gated on
  `service_completed_successfully` and no published ports on PostgreSQL or Redis.
* The Dockerfile has **not been built or run here.** CI builds all four targets
  and asserts each image runs as a non-root user; that job has not executed in
  this environment.
* `scripts/deploy.sh` preflight guards were exercised individually (missing env
  file, placeholder hostname, placeholder secret, fake detector) and all four
  refuse correctly. The build and start phases could not run without a daemon.
* `scripts/generate-secrets.sh` was run and its output was fed through
  `Settings(environment="production")`, which **accepted it** — so the generator
  produces a configuration the application will actually start on.

Integration and E2E were run against natively-installed PostgreSQL, Redis, and a
mail catcher instead of containers, so the behaviour they cover is verified even
though the images are not.

## Residual limitations

1. **No calibration.** The identity mapping is in force and says so. Every
   result records `calibration_version` so stored results stay interpretable.
2. **No measured accuracy.** See above. This is a property of the project, not
   of the environment.
3. **Encryption key rotation is not implemented.** Envelopes are versioned so a
   new key can be introduced, but there is no re-encryption migration for
   existing rows. Rotating today makes previously stored text undecryptable;
   the application reports a decryption failure rather than returning corrupt
   data. Documented in `PRIVACY_AND_RETENTION.md`.
4. **The retention sweep is not self-scheduling.** It is a Celery task and a CLI
   command; the operator must schedule it.
5. **Analysis runs inline in the request.** The Celery path is implemented,
   tested, and used by the retention sweep, but text submission currently
   completes synchronously. That is correct for the CPU model sizes in scope and
   simplifies the guest flow; a slower model would want the queued path, and the
   status-polling endpoint and frontend poller already exist for it.
6. **Prometheus metrics are a stub.** `ORIGINLENS_METRICS_ENABLED` is validated
   and refuses to run without a token in production, but no metrics endpoint is
   implemented yet.
7. **Language detection is English-only** and uses a small-profile library that
   is itself unreliable on very short text. The 80-word minimum mitigates this.
8. **`X-Forwarded-For` is not trusted.** Rate limiting uses the socket peer, so
   behind a proxy every client shares one identifier until
   `client_identifier()` is adapted. Documented in `DEPLOYMENT.md` with the
   condition under which it is safe to change.
9. **Container images are unbuilt here.** The Dockerfile was restructured into
   four targets (`api`, `worker`, `migrate`, plus the shared `runtime` base)
   because the previous worker image began `FROM originlens-api:latest`, which
   would have made `docker compose build` fail on a clean checkout. The fix is
   correct by construction — each target builds independently from the same
   file — but it has not been built and run in this environment.

## Honest summary

The application starts, migrates, and works end to end against real PostgreSQL,
Redis, and Celery. Guest and registered flows, document upload, administration,
authorization boundaries, and the privacy controls are implemented and covered
by 453 passing tests. The real model provider is implemented and exercised
against a real transformer, and the two bugs that found are fixed.

What cannot be claimed from this environment: that a **published** detector
loads and performs well, and that the container images build. Both are
implemented and covered by CI or an explicit operator command, and neither has
been run here.
